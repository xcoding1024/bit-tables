# 故障排查

## 打开目录后没有配置表

确认选择的是包含 `tables` 的项目根目录，而不是 `tables` 本身。配置表目录必须包含 `<目录名>_struct.yaml`，且表 ID 以小写字母开头，只包含小写字母、数字和下划线。

## 单元格不能编辑

普通表格需要双击单元格。底部带 Excel 图标的 Sheet 是只读来源，不能直接修改；请在 Excel 中修改并保存，或把值通过插件写到普通配置表。

## 修改后没有写入文件

确认已经点击“保存”或按 `Ctrl/Cmd+S`。若保存后出现检查错误，按右侧规则修正；再查看底部日志中的具体文件或脚本错误。

## Excel 公式无法作为来源

用 Excel 打开文件并重新计算、保存，确保公式带缓存值。错误公式、缺少缓存和超出工作表范围都会使插件拒绝应用。

## 插件列表为空

插件按当前目标的表、Sheet、字段、类型和控件匹配。先选择普通配置表中的单元格或整列；Excel 只能作为来源，不能作为插件目标。

## 检查错误没有定位

确保检查器返回的路径属于当前 Sheet，例如 `sheets.items.rows.0.id`。在编辑器中点击“下一个错误”；仍无法定位时展开底部日志查看原始错误。

## 导出目录没有文件

确认当前表存在 `_export.ts` 或兼容的 `_export.js`，并查看导出对话框是否显示跳过或错误。产物位于项目根目录的 `build/client` 和 `build/server`，不在 `tables` 内。

## 历史记录为空

历史只读取 Git/SVN 已提交记录。复制出来的示例目录、尚未提交的新文件或不在工作副本中的目录都不会显示历史。
